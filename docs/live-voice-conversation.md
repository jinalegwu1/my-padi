# Live voice conversations

During a call, microphone frames go through echo suppression and a short
on-device speech detector. The app retains up to 500 ms of pre-roll to capture
the first syllable. Nigerian English, Nigerian Pidgin and UK English can use
one authenticated WebSocket per call. The recognizer returns revisable captions
while the user speaks. Once speech ends, the client commits one final transcript
to the selected conversation. The transcript control follows the preference in
Settings. A new utterance interrupts speech and discards queued audio.

One continuous second of silence ends a turn. Speaking again during that
second restarts the timer. On short web turns, the live recognizer can prepare
the final words during the pause. The client sends them to chat once the turn
ends and recognition is complete. Other input locales and servers offering
only file recognition use Faster-Whisper on the complete utterance.

## Speech delivery

The Go chat route streams text using the configured voice chat model. The same
words appear on screen and enter synthesis at sentence or short clause boundaries.
For Nigerian English and Pidgin the Python service plans the prosody of a phrase,
then decodes its waveform in overlapping windows. Only the center of each window
enters the playback queue. Go validates the 24 kHz PCM WAV packets and the client
credits a spoken phrase once its last packet finishes playing. Both previews
and live calls use the user's selected voice and pace.

In live calls, playback starts as soon as the first audio packet arrives. If
the speech engine generates audio more slowly than it plays, there can be
audible pauses between packets.

On the web call screen, **Fast English voice** uses eSpeak NG for a quicker,
more synthetic reading. The option appears for English and Pidgin calls when
the local speech service provides English output. The browser remembers the
choice for future calls. Changing it during a reply takes effect on the next
reply. Recognition and the conversation still use the selected language.

Select PADI or Ada in Settings → Voice. These four samples were generated by
the local checkpoints used by the application.

Listen for pronunciation of Ada and Abuja, the cadence of the question, and the
tone of reassurance. Nigerian English and Pidgin listeners should assess these
on phone speakers. The live acoustic model is general English. In the repository’s
recorded Nigerian English sample it split “invoices” into “in voices”. On the
Pidgin sample it misheard several words including “pikin”.

## Setup and timing

Run `npm run setup:voice`, enable the local voice engine and speech recognition,
and restart the Python and Go services. Both weights and the tokenizer load
from local files. On deployment hosts with a compatible PyTorch build the speech
engine can use CUDA or Apple MPS. `PADI_NIGERIAN_VOICE_DEVICE` can select
`cpu`, `cuda`, or `mps` explicitly. A TLS reverse proxy must pass WebSocket
upgrades on `/v1/voice/listen` and flush streaming responses on `/v1/chat` and
`/v1/voice/speak`. Android and iOS require an Expo development build.

The acceptance target uses 100 warm turns on a good connection. For at least 95,
the first visible reply and first audible reply must both occur within three seconds
of the last spoken word. Also test the first caption, long mid-sentence pauses,
speaker echo, noise, barge-in and continuous playback. The following browser
User Timing entries contain durations only. Confirm perceived sound with a physical
phone, including speakerphone and Bluetooth.

| Measure | Starts | Ends |
| --- | --- | --- |
| `padi.voice.first-caption` | Detected speech onset | First provisional caption |
| `padi.voice.submit` | Last voiced microphone frame | Final text sent to chat |
| `padi.voice.first-reply-text` | Last voiced microphone frame | First reply delta presented to the UI |
| `padi.voice.first-playback` | Last voiced microphone frame | Player start callback |

On the two-core Celeron J4005 used for development, a warm full-phrase CPU
benchmark took 10.85 seconds to synthesize two seconds of a male voice. Streamed
packets allow earlier playback, but this host cannot sustain the requested
latency and smooth delivery at that rate. A faster inference host and a real
phone test are needed for acceptance. See the [voice service setup](../services/voice/README.md).
